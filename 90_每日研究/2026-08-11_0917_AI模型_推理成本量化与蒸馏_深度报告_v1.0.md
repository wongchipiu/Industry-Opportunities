## 一页结论

- 核心判断：推理经济学正在从“谁拥有最大模型”转向“谁能把每个任务路由到最低足够成本”。价格表已经把这一点显性化：OpenAI同一旗舰族从 gpt-5.6-sol 到 gpt-5.6-luna 的标准短上下文输入/输出价差约25倍；Anthropic Sonnet 5通过缓存命中把输入成本从US$2/MTok降至US$0.20/MTok；Google Gemini 3.5 Flash-Lite标准价为US$0.30/US$2.50，Batch/Flex为US$0.15/US$1.25（来源见文末）。
- 当前周期位置：推理处在“价格快速分层、软件优化继续释放吞吐、企业量产尚在早期”的阶段。硬件层继续受益，但超额利润不只来自GPU数量，还来自KV cache管理、batching、speculative decoding、量化、蒸馏、缓存折扣和任务路由。
- 最大预期差：单位token价格下降不必然利空模型和硬件。若降价带来更高调用量、更多agent步骤和更长上下文，计算总量可能继续上升；但利润池会从通用大模型API单价，迁移到高利用率云平台、推理加速硬件、企业数据入口和能做成本路由的软件层。
- 最值得跟踪的三个指标：主流模型API的输入/输出/缓存/Batch价差，单位token硬件成本与MLPerf/InferenceX吞吐，企业推理调用量或AI云收入相对CapEx/折旧的覆盖率。
- 全球标的优先级：Microsoft、NVIDIA、Alphabet、Broadcom、Amazon、AMD、Cloudflare。因实时估值与目标价未完整核验，本报告不升级任何标的为“候选”。

## 1. 定义与研究边界

本报告研究大模型推理成本如何下降，以及量化、蒸馏、缓存和路由如何改变产业链利润池。覆盖云端和边缘推理，不覆盖单一聊天产品体验，也不把某个模型的benchmark排名等同于可投资结论。

- 事实：OpenAI官方定价页显示，gpt-5.6-sol标准短上下文为输入US$5.00/输出US$30.00每百万token，gpt-5.6-luna为输入US$0.20/输出US$1.20；Batch价约为标准价的50%，Fast mode约为标准价2倍（来源：[OpenAI API Pricing](https://developers.openai.com/api/docs/pricing)）。
- 事实：Anthropic Claude Sonnet 5在2026-08-31前为输入US$2/输出US$10每百万token，缓存命中/刷新为US$0.20/MTok；2026-09-01起标准价转为US$3/US$15（来源：[Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)）。
- 事实：Google Gemini 3.5 Flash-Lite定位高吞吐agent任务，标准文本输入/输出价为US$0.30/US$2.50，Batch/Flex为US$0.15/US$1.25（来源：[Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)）。
- 推断：模型厂商开始以“旗舰/中档/轻量 + 缓存 + Batch/Flex/Priority”方式对同一需求曲线分层定价，实际单位成本取决于任务路由和上下文复用，而非单一模型标价。
- 观点：投资上应把推理看成运营效率问题。赢家不是简单“最强模型”，而是能把硬件利用率、模型压缩、缓存命中、企业工作流和计费分层同时做好的平台。

## 3. 需求、供给与周期

### 需求

企业需求从试点聊天转向工作流内嵌：代码生成、客服总结、搜索增强、销售助手、文档处理和agent执行都会把一次用户请求拆成多次模型调用。Amazon 2026Q2披露AWS收入US$42.2B、同比+37%，AWS operating income US$16.6B；Microsoft和Alphabet在上一轮报告中已披露商业RPO和Cloud backlog高增。这说明云端AI需求仍强，但投资结论必须看AI收入能否覆盖数据中心折旧和推理毛利。

### 供给

供给端发生三件事：

1. 硬件单位成本继续下降。NVIDIA官方推理性能页引用SemiAnalysis InferenceX称，Blackwell B200在GPT-OSS-120B上每百万token成本两个月内从US$0.11降至US$0.02，主要来自TensorRT-LLM和Dynamo软件栈优化；NVIDIA MLPerf页同时列示Inference v5.1/v6.0结果及其非官方token成本口径。
2. 模型族内部成本分层更细。OpenAI、Anthropic和Google均提供缓存、Batch/Flex或Fast/Priority等定价层；企业真实成本将由“命中率、排队容忍度、输出长度和模型选择”决定。
3. 压缩技术可把任务下沉到更便宜模型。vLLM/PagedAttention通过接近零浪费的KV cache管理提高吞吐；AWQ显示保护约1%显著权重可降低低比特量化误差，并在TinyChat中实现对FP16基线超过3倍的加速。

### 周期位置

推理仍处在早期放量期，尚未到“降价吞噬利润”的单一路径。当前更像云计算早期：单位价格下降、用量弹性上升、平台为留住工作负载主动优化成本。若未来两个季度AI云收入和应用留存继续上行，推理降价是需求扩张；若调用量增速低于价格下降和CapEx折旧增速，则进入毛利率压力阶段。

## 4. 技术路线与成本曲线

| 路线 | 降本机制 | 事实基础 | 投资含义 | 相反证据 |
|---|---|---|---|---|
| 缓存与上下文复用 | 重复系统提示、工具定义和长文档只付较低缓存价 | Anthropic Sonnet 5缓存命中US$0.20/MTok；OpenAI gpt-5.6-sol cached input为标准输入的10% | 利好企业长上下文工作流、云平台和能提高命中率的应用架构 | 新任务/开放域任务缓存命中低，长上下文仍消耗存储和延迟 |
| Batch/Flex路由 | 非实时任务接受排队换低价 | OpenAI和Gemini Batch约为标准价50% | 离线分析、客服质检、数据处理等低延迟敏感任务放量 | 实时agent、语音和交易场景不能等 |
| KV cache管理 | 减少显存碎片和过度预留，提高并发 | PagedAttention/vLLM宣称near-zero waste和跨请求共享KV cache | 高利用率推理平台的单位成本更低，利好云和软件栈 | 调度复杂度上升，极长上下文仍受显存和带宽限制 |
| 量化 | FP16/BF16转INT8/INT4/FP4/FP6，降低显存和带宽 | AWQ、AMD MI350 MXFP6/MXFP4、NVIDIA Blackwell低精度路径 | 推理硬件更看重内存带宽、低精度吞吐和软件生态 | 精度损失、校准数据偏差和任务安全要求限制极低比特 |
| 蒸馏 | 用大模型输出/生产数据训练小模型 | OpenAI Model Distillation支持Stored Completions、Evals和fine-tuning流程 | 企业可把高频稳定任务从旗舰模型迁移到低价小模型 | 数据治理、评测不足或任务分布漂移会导致小模型失效 |
| Speculative/路由 | 小模型先草稿，强模型验证；按任务选择模型 | 产业实践广泛采用，但公开量化披露有限 | 利好拥有多模型组合和路由层的平台 | 若强模型验证成本高或错误代价高，节省有限 |

关键结论：推理成本下降不是单一技术曲线，而是“硬件低精度 + 软件调度 + 模型压缩 + 商业定价 + 应用架构”的叠加。投资者需要跟踪有效成本，而不是只比较模型榜单。

6. 版权、数据驻留和安全监管是否提高蒸馏/日志训练成本。

## 10. 催化剂、风险与证伪

### 催化剂

- OpenAI、Anthropic、Google、Alibaba、DeepSeek继续降低低价模型和Batch/Flex成本，同时企业调用量、AI云收入和RPO保持高增。
- NVIDIA/AMD/Broadcom披露推理负载收入占比、单位token成本、Blackwell/MI350/定制ASIC客户扩张。
- MLPerf Inference或公开基准显示Blackwell/AMD/ASIC在真实长上下文和agent工作负载上继续提升吞吐和能效。
- 企业软件厂商披露AI毛利率、推理成本占收入比例下降，证明蒸馏和模型路由有效。

### 风险

- API降价速度快于调用量增长，模型和云平台毛利率被压缩。
- 企业agent调用复杂度上升导致输出token、工具调用和上下文成本失控。
- 低比特量化或蒸馏在高风险任务中精度不足，带来安全、合规和品牌风险。
- 客户自研ASIC和开源推理栈削弱NVIDIA溢价，或定制ASIC项目集中暴露Broadcom风险。
- 数据驻留、版权和日志训练限制提高蒸馏成本。

### 证伪条件

- 主流模型API价格连续两轮下调，但主要云厂商AI收入/RPO或应用留存没有同步改善。
- NVIDIA或主要云厂商披露推理利用率不足，GPU/ASIC折旧拖累毛利率。
- 企业软件AI功能付费转化低于预期，AI调用成为成本中心而非收入中心。
- 蒸馏/小模型在真实生产任务中错误率明显高于旗舰模型，客户回退到高价模型。
- 开源模型和边缘推理导致API平台缺乏定价权，但未带来足够硬件增量。
